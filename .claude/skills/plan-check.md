# Skill: plan-check - 事業計画の進捗確認・差分分析

## 概要
策定した事業計画に対する実績の進捗を確認し、差分の原因分析とリカバリー策を提示する。

## トリガー
計画の振り返り、実績との比較、予実管理、月次レビューを依頼された場合。

## 入力情報（ユーザーに確認する項目）
- 対象期間
- 計画値（売上、利益、受注件数等）
- 実績値
- 主要な出来事（受注/失注/遅延/人員変動等）

## 出力内容

### 1. 予実比較サマリー
```
| 指標 | 計画 | 実績 | 差分 | 達成率 | 判定 |
|---|---|---|---|---|---|
| 売上 | X万円 | X万円 | ±X万円 | XX% | 🟢/🟡/🔴 |
| 粗利 | X万円 | X万円 | ±X万円 | XX% | |
| 受注件数 | X件 | X件 | ±X件 | XX% | |
| 稼働率 | XX% | XX% | ±X% | - | |
| 営業活動数 | X件 | X件 | ±X件 | XX% | |
```

### 2. 差分の原因分析
- **ポジティブ要因**: 計画を上回った要素とその理由
- **ネガティブ要因**: 未達の要素とその理由
- **外部要因 vs 内部要因**: コントロール可能/不可能の切り分け

### 3. 着地見込み
- 現在のペースで期末まで進んだ場合の着地予測
- 楽観/標準/悲観の3パターン

### 4. リカバリーアクション（未達の場合）
- **即効性のある施策**: 既存クライアントへのアップセル、単価交渉
- **中期施策**: 営業活動の強化、チャネル開拓
- **コスト面**: 外注比率の調整、固定費の見直し

### 5. 計画修正の要否
- 当初計画を維持するか、修正するかの判断材料を提示
- 修正する場合の修正版ドラフト

## 判定基準
- 🟢 達成率 90%以上: 順調
- 🟡 達成率 70-90%: 注意（原因分析と対策必要）
- 🔴 達成率 70%未満: 要対応（計画修正を検討）
