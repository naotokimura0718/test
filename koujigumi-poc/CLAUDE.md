## プロジェクトの目的

鴻治組様の設計図面から以下を自動化するAIシステムのPoC：

1. **基本設計段階での概算積算**
   - 構造図が整う前に、用途・スパンから原単位を推定して概算を出す
   - 従来10〜14日かかる読み取り・拾い出しをAIで数日に短縮

2. **サッシ回り等の構造的成立性チェック**
   - 単純な「間違い指摘」ではなく、「構造的に成立するかの判断」
   - 明かり/燈・セコードテック等の既存AIとの差別化ポイント

## 技術方針

**Phase 1（MVP・現在）**: Claude API主体
- Anthropic Claude Sonnet 4（claude-sonnet-4-6）を使用
- マルチモーダル入力（PDF → Base64画像）でビジョン機能を活用
- プロンプトエンジニアリング中心、複雑なパイプラインは組まない

**Phase 2（精度不足時のみ）**: ハイブリッド
- PyMuPDFでテキスト・表を抽出
- OpenCV/CV技術で図面領域を検出
- 構造化データをLLMに渡す

判断基準：Phase 1で積算誤差が±10%を超える、または構造チェックのPrecisionが50%を下回る場合にPhase 2を検討。

## 重要な業務知識

### 積算の8ステップ（鴻治組ヒアリング反映）

1. 建物概要の把握（用途・構造・階数・延床面積）
2. 仕上の読み取り（内部仕上表・外部仕上表から）
3. 面積の算出（平面図・求積図・矩計図から）★
4. 内装仕上げ数量の積算
5. 躯体数量の概算（★基本設計段階では原単位推定が必要）
6. 設備・外構・仮設概算
7. 集計・見積書作成
8. 精度確認・検算

**鴻治組ヒアリングで判明した重要ポイント：**
- STEP1〜3の「読み取り・拾い出し」で1案件10日〜2週間
- 基本設計段階では構造図・設備図が未確定（PDFまたはスキャン画像）
- 顧客から「2週間で概算を」と求められるが過去実績の手作業では間に合わない
- これに応えるための「用途×構造×スパン → 原単位推定」がメイン機能

### 構造チェックの差別化ポイント

**競合（明かり/燈、セコードテック）：**
- 「間違いの指摘」が中心（寸法違い、記号矛盾等）
- 複数図面を参照した整合性チェック

**本PoCの差別化：**
- 「構造的に成立するかの判断」
- 特に**サッシ回り**（柱・壁の位置とサッシの取り合い、防水と構造の両立）
- 施工経験がないと気付けない指摘を、鴻治組様の過去判断を学習して実現

### 図面の実態

- 基本設計段階はPDFまたはスキャン画像が多い
- BIMデータはほぼない
- 構造図・設備図が未確定のケース多数
- 設計事務所からの図面は品質にばらつきあり

## 開発ルール

### コーディングスタイル

- **Python 3.11+** 必須（`match` 文、`typing.Self` 等を使う）
- **型ヒント必須**：関数シグネチャには必ず型をつける
- **docstring**：複雑な関数には Google style で記述
- **async** 推奨：Claude API呼び出しは非同期で並列化
- **pydantic** で入出力データのスキーマを定義

### プロンプト設計

- プロンプトは `src/prompts/*.py` に関数として実装
- プロンプトは日本語メインでOK（建設用語は日本語固有）
- few-shot examples を積極的に使う（鴻治組様の過去判断を学習データ化）
- 出力は必ずJSON形式で返させる（`response_format` 活用）

### データ取り扱い（重要）

- `data/drawings/` および `data/ground_truth/` はNDA対象データ
- **絶対にGitにコミットしない**（.gitignoreで除外済み）
- ログに図面の内容を出力しない（ファイル名のみOK）
- PoC終了後は鴻治組様の指示に従って削除する

### テストデータ

- NDA前はダミー図面で開発（`data/reference/` のサンプル）
- 既存の `ref/koujigumi-demo.jsx` で使ったサンプルデータを正解例として利用

## よくある作業パターン

### 積算パイプラインを実行したい

```bash
python scripts/run_estimation.py --input data/drawings/sample.pdf
# → results/estimation_<timestamp>.json が生成される
```

### 構造チェックを実行したい

```bash
python scripts/run_structural.py --input data/drawings/sample.pdf
# → results/structural_<timestamp>.json が生成される
```

### 精度評価したい

```bash
python scripts/evaluate.py --predictions results/ --ground-truth data/ground_truth/
# → results/evaluation_report_<timestamp>.md が生成される
```

### プロンプトを改善したい

1. `src/prompts/*.py` を編集
2. `tests/` 配下の該当テストを実行
3. 複数ケースで検証してから本実行
