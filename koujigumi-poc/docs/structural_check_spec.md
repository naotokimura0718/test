# 構造チェック仕様

檜山様ヒアリングで判明した「差別化ポイント」を実装するための仕様。

## 背景

### 競合（明かり/燈、セコードテック等）

既存のAI図面チェッカーは、以下のような「表層的なチェック」が中心：

- 寸法の数値違い
- 記号の矛盾
- 仕上表と平面図の部屋名不一致
- 面積の計算ミス

これは「設計図通りに施工すれば成立する」という前提のチェック。

### 本PoCの差別化

**「設計図そのものが施工可能か」を判断する。**

鴻治組様のベテラン40年の経験を学習データ化し、以下を実現：

1. **サッシ回りの構造的成立性**（最重要）
2. **意匠と構造の整合性**（設計事務所では気付きにくい点）
3. **防水と構造の両立判断**

## チェック項目の分類

### レベル 1: 単純チェック（既存AIでも可能）

これらはベースライン機能として実装するが、差別化要素ではない。

- 寸法記載ミス
- 仕上表と平面図の部屋名不一致
- 面積表と求積図の値の相違
- 特記仕様書と仕上表の齟齬

### レベル 2: サッシ回り構造チェック（差別化の核）

#### 2-1. サッシ開口と壁厚の関係

**チェック内容：**
- サッシ開口幅に対する両側の壁厚が十分か（推奨 300mm以上）
- 方立・無目の固定が構造的に可能か
- 躯体との取り合い寸法の検証

**ベテラン判断の例（鴻治組事例）：**
> サッシ開口2,700mmに対し壁厚150mmだった案件：
> 壁厚を250mmに増やすか、方立を梁に直接固定する納まりに変更。
> そのままでは方立の固定が構造的に不安定で、地震時にサッシ脱落リスクあり。

#### 2-2. サッシ位置と柱・梁の干渉

**チェック内容：**
- サッシと柱の干渉
- サッシ上端と梁下端のクリアランス（推奨 100mm以上）
- サッシ下端と躯体の納まり

**ベテラン判断の例：**
> サッシ下端と梁下端のクリアランスが80mmの案件：
> 防水処理が困難になるため、サッシ高さを調整するか納まり詳細図を要請。

#### 2-3. 防水と構造の両立

**チェック内容：**
- サッシ枠の防水立ち上がり寸法
- 水切り・シール処理の納まり
- 雨仕舞いと構造体の関係

### レベル 3: 意匠・構造整合性チェック

**チェック内容：**
- 意匠図の柱位置 vs 構造図の柱位置
- 意匠図で遮るブレースがないとされる位置に、構造図ではブレース配置
- 梁せい・梁幅の矛盾
- 壁の有無の矛盾

**ベテラン判断の例：**
> エントランスFIX窓の位置にブレース配置が矛盾した案件：
> 意匠図では視界を遮らない設計、構造図ではX型ブレース配置。
> 施工時に意匠変更が必須になるため、早期の意匠・構造調整が必要。

### レベル 4: 施工成立性チェック

**チェック内容：**
- 配筋が施工できる空間があるか
- 型枠が組める納まりか
- 資材・機材の搬入動線

これは長期的な目標、Phase 1では範囲外。

## 出力フォーマット

```python
class StructuralIssue(BaseModel):
    """構造チェックの指摘事項"""
    severity: Literal["critical", "warning", "info"]
    category: Literal[
        "window_structural",      # サッシ回り構造
        "design_consistency",     # 意匠・構造整合性
        "waterproofing",          # 防水・構造両立
        "simple_check",           # 単純チェック（レベル1）
    ]
    location: str                 # 「3F南面 会議室」等
    issue: str                    # 1行で問題点
    detail: str                   # 詳細な説明
    reference: str | None         # 鴻治組過去事例
    recommended_action: str       # 推奨アクション
    confidence: float             # 0.0〜1.0
    related_drawings: list[str]   # 参照した図面名
```

### 重要度の基準

**critical（重要指摘）:**
- 手戻り工事で数百万〜数千万円の損失が想定される
- サッシ脱落等、構造的に危険
- 施工不可能な設計

**warning（警告）:**
- 施工可能だが品質リスクあり
- 推奨範囲外の寸法

**info（情報）:**
- 軽微な齟齬
- 念のための確認事項

## プロンプト設計の核

### System Prompt

```
あなたは広島の地場ゼネコン「鴻治組」の建築部で40年の経験を持つ
ベテラン施工管理者です。

設計事務所から提出された図面を見て、「設計図通りに施工できるか」を
判断します。単なる寸法違いや記号矛盾の指摘ではなく、「現場で実際に
成立するか」を判断することが重要です。

特に以下の観点で厳しくチェックしてください：

【最重要】サッシ回りの構造的成立性
- サッシ開口に対する壁厚・躯体の取り合い
- 方立の固定が構造的に可能か
- 防水と構造の両立ができるか

【重要】意匠・構造の整合性
- 柱・壁・ブレース位置の図面間不一致
- 梁下端とサッシ上端のクリアランス

【基本】単純な不整合
- 寸法記載ミス、仕上表と平面図の不一致等

指摘の際は以下を必ず明記してください：
1. 重要度（critical / warning / info）
2. 場所（階・面・部屋を具体的に）
3. 問題点と、なぜ問題なのか
4. 鴻治組の過去事例があれば参照
5. 推奨アクション
```

## 学習データの整備計画

### NDA後のデータ受領

鴻治組様から以下を受領：
- 過去の設計図面 2〜3物件
- 同物件の拾い出し数量
- **（交渉可能なら）**過去の質疑書（RFI）と鴻治組側の指摘事項

### 学習データ化

1. 過去の質疑書から「ベテランが指摘した問題点」を抽出
2. 問題点を上記のスキーマ（StructuralIssue）にマッピング
3. few-shot examples として構造化
4. 段階的にプロンプトに追加して精度評価

### 将来のスケールアップ

学習データが蓄積されたら、Fine-tuning または RAG による精度向上を検討：

- **RAG**: 過去事例を Vector DB に格納、類似事例を検索してプロンプトに注入
- **Fine-tuning**: 十分なデータ（数百件以上）が集まってから

## 精度評価

### 評価指標

- **Precision**: AIが指摘した内容のうち、ベテランが「正しい指摘」と認めた割合
- **Recall**: ベテランが指摘すべき内容のうち、AIが検出できた割合
- **Severity accuracy**: 重要度の判断精度

### 評価手順

1. 鴻治組様から受領した図面に対してAIを実行
2. AIの指摘事項を鴻治組様（檜山様）にレビューいただく
3. 各指摘を「正しい / 不要 / 見落とし」の3分類
4. Precision / Recall を算出
5. 見落とし（False Negative）を分析してプロンプト改善

### 目標値

| 指標 | Phase 1目標 | 最終目標 |
|------|-----------|---------|
| Precision | 60% | 80% |
| Recall | 40% | 70% |
| Critical指摘のRecall | 70% | 95% |

※ Critical指摘のRecallは特に重要（見落とすと損失大）
